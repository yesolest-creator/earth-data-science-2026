웹앱 구현 및 점검

읽는 데 약 5분

이 페이지에 입력한 내용은 저장되지 않습니다. 새로고침하거나 페이지를 벗어나면 사라지니, 필요한 내용은 따로 기록해 두세요.

01이 단계에서 할 일

구현부터 제출까지 네 단계

기획안에서 완성한 프롬프트를 AI 코딩 도구에 전달해 웹앱을 만들고, 제출 전까지 아래 네 단계를 거칩니다.

  1. 프롬프트로 구현 시작기획안에서 완성한 1·2단계 프롬프트를 AI 코딩 도구에 순서대로 전달합니다.
  2. 반복 점검·디버깅결과물을 직접 열어보고, 의도와 다른 부분을 AI에게 다시 전달해 고쳐나갑니다.
  3. 제출 전 점검체크리스트로 스스로 점검하고, AI에게도 최종 점검을 맡깁니다.
  4. 결과 보고서 작성·제출완성된 웹앱을 바탕으로 보고서를 쓰고, 웹앱 파일과 함께 제출합니다.

02구현 진행 가이드

AI와 주고받으며 완성하기

기획안에서 완성한 프롬프트를 AI 코딩 도구에 전달하면 웹앱 초안이 나옵니다. 이후 과정은 한 번에 완성되지 않고, 확인과 수정을 여러 차례 반복하며 다듬어집니다.

반복 점검 흐름

1단계·2단계 프롬프트를 순서대로 붙여넣어 초안을 받습니다. 나온 파일을 브라우저에서 직접 열어 실제로 어떻게 작동하는지 확인합니다.

의도와 다르게 작동하거나 오류가 있다면, 무엇이 어떻게 다른지 구체적으로 설명해 AI에게 다시 전달합니다. 화면을 캡처해 함께 전달하면 더 정확하게 고쳐집니다.

이 과정을 필요한 만큼 반복합니다. 코드를 직접 고칠 필요는 없습니다 — AI와의 대화로 계속 수정합니다.

막히는 부분이 있다면 무엇을 시도했고 어떤 결과가 나왔는지 구체적으로 적어 AI에게 전달하세요. "안 돼요"보다 "이 버튼을 눌렀을 때 그래프가 비어 있어요"가 훨씬 빨리 해결됩니다.

AI에게 최종 점검 맡기기

■ 보안·개인정보 점검 (반드시 확인)
지금까지 만든 코드 전체를 다시 살펴보고, 아래 항목이 하나라도 있으면 찾아서 알려주고 고쳐줘.
- API 키, 토큰, 비밀번호가 코드 안에 그대로 노출된 부분
- localStorage, sessionStorage 등 브라우저 저장 기능을 사용한 부분
- 방문자의 이름·이메일·위치 등 개인정보를 입력받거나 수집하는 부분
- 인증키가 필요한 외부 API를 호출하는 부분

■ 파일 형식 점검
- 결과물이 index.html 파일 하나로만 되어 있는지 확인해줘.
- CSS와 JavaScript가 각각 <style>, <script> 태그 안에 전부 포함되어 있고, 별도의 .css·.js 파일을 참조하지 않는지 확인해줘.

■ 기능 점검
- 우리가 "필수 기능"으로 정했던 것들이 실제로 오류 없이 작동하는지 하나씩 확인해줘.
- 작동하지 않거나 불완전한 부분이 있다면 무엇인지, 왜 그런지 설명해줘.

■ 의사소통 점검
- 이 주제를 처음 보는 사람이 됐다고 가정하고 웹앱을 다시 봐줘.
- 그래프나 텍스트만으로 우리가 전달하려는 핵심 내용이 이해되는지, 오해할 수 있는 표현이나 데이터가 뒷받침하지 않는 과장된 결론은 없는지 확인해줘.

■ 정리해서 보고
위 네 가지를 각각 "문제 없음" 또는 "문제 발견 — 내용" 형태로 정리해서 보여줘. 문제가 있는 항목은 어떻게 고칠지 먼저 설명하고, 내가 확인한 뒤에 수정을 지시하겠다.

04결과 보고서 작성

루브릭 다섯 영역 기준

완성된 웹앱을 바탕으로 아래 다섯 항목을 서술합니다. 각 항목의 "참고"는 이 항목이 어떤 평가 기준에 대응하는지 보여주는 요약이며, 그대로 옮겨 적는 게 아니라 서술의 방향을 잡는 데 참고합니다.

보고서 맨 위에 웹앱 제목을 적습니다. 기획안 제출 시점과 제목이 달라졌을 수 있으니, 기획안에 적었던 제목이 아니라 완성된 웹앱의 <title>과 동일한 최종 제목을 적습니다.

1. 웹앱 개요

기획의 구체성 · 4점 — 관찰·연결·임팩트·요청 4단계를 모두 채웠다 / 각 단계마다 구체적인 데이터와 근거를 사용하였다 / 실행 가능한 수준까지 기획을 구체화하였다

기획안에서 세운 관찰-연결-임팩트-요청이 최종 웹앱에서 어떤 모습으로 구현되었는지, 기획과 달라진 부분이 있다면 무엇이 왜 달라졌는지 서술합니다.

2. 데이터 출처와 처리 과정

데이터 리터러시 · 3점 — 데이터 출처와 처리 과정을 투명하게 제시하였다 / 이상치·표본 왜곡 등 통계적 오류 없이 분석하였다

어떤 데이터를 어디서 가져와 어떤 과정을 거쳐 웹앱에 쓰이는 형태로 만들었는지, 데이터를 다루며 주의하거나 걸러낸 부분(이상치·결측·표본의 한계 등)이 있었다면 함께 서술합니다.

3. 분석 결과와 근거

과학적 타당성 · 3점 — 데이터가 뒷받침하는 범위 안에서 결론을 도출하였다 / 근거와 주장 사이에 논리적 비약이나 과잉 일반화가 없었다

분석을 통해 무엇을 알아냈는지, 그 결론이 데이터의 어느 지점에서 어떻게 뒷받침되는지 구체적 수치와 함께 서술합니다.

4. 전달 방식

의사소통 효과성 · 3점 — 비전공 일반 대중이 이해할 수 있는 언어와 시각화를 사용하였다 / 핵심 메시지를 명료하고 과장 없이 전달하였다

이 주제를 처음 보는 사람에게 잘 전달되도록 웹앱을 어떻게 설계했는지, 언어와 시각화에서 내린 선택과 그 이유를 서술합니다.

5. 웹앱 스크린샷

웹앱 완성도 · 2점 — 웹앱이 오류 없이 작동하였다 / 기본적인 완성 수준을 갖추었다

핵심 화면 1~2장을 첨부하고, 웹앱이 실제로 어떻게 작동하는지 화면과 함께 간단히 설명합니다. 기술적 문제로 웹앱이 정상 작동하지 않을 경우, 이 항목이 평가 근거 자료 역할을 합니다.
